# v1.13.0

Luminous MCP 1.13 makes curating artist profiles from an AI assistant safe and fast: profile writes no longer race the desktop app, a typo can't create an orphan profile, tags can be added or removed in bulk, artists carry a country, and an enforceable tag vocabulary keeps spellings from drifting. It also adds a tool that lists every artist in your library and packages the server as a Claude plugin.

### 🎤 Artists
- **List every artist** ([#101](https://github.com/esoltys/luminous-mcp/issues/101)): The new `list_artists` tool enumerates every artist in your library with their track counts and whether they have a curated profile. Filter by name, by country, or to only artists with or without a profile, and sort by name or track count.
- **Country on artist profiles** ([#103](https://github.com/esoltys/luminous-mcp/issues/103)): `get_artist_profile`, `find_artists_by_tag` and `list_artists` show each artist's country as an ISO code plus its name, and `update_artist_profile` can set it for artists with no MusicBrainz match. Nothing is looked up live: the value comes from the Luminous database, which fills it in from MusicBrainz. Needs a Luminous version with schema 84 or later; older libraries simply show no country.
- **Profile or no profile?** ([#104](https://github.com/esoltys/luminous-mcp/issues/104)): `get_artist_profile` now says whether an artist is `curated`, in your library but without a profile yet, or `not_found`, instead of returning an empty profile for all three. Updating a name that isn't in your library is rejected with the closest library names suggested; pass `allow_unknown_artist` when you mean it. Updates report whether they created a new profile.
- **Library spelling wins** ([#105](https://github.com/esoltys/luminous-mcp/issues/105)): Profiles come back under your library's spelling of the artist, such as "The War on Drugs", whatever casing was used to write them. If the stored key still differs, it is shown alongside.

### 🏷️ Tags
- **Add or remove tags, in bulk** ([#102](https://github.com/esoltys/luminous-mcp/issues/102)): `update_artist_profile` accepts `add_tags` and `remove_tags` so changing one tag no longer means reading and rewriting the whole list. The new `update_artist_profiles` applies changes to up to 500 artists in one call and reports each artist as created, updated, unchanged or failed without stopping the batch. Adding is case-insensitive and keeps order; removing a tag that isn't there does nothing.
- **See and control which tags are used** ([#106](https://github.com/esoltys/luminous-mcp/issues/106)): `list_artist_tags` lists every tag in use with its artist count, groups spellings that differ only by case, and marks each as allowed, denied or unknown. `get_tag_policy` shows the rules, and `update_artist_profile` checks new tags against them with a suggested replacement for near misses. The built-in rules allow nationality and named-award tags and deny genre and decade or era tags; point `LUMINOUS_ARTIST_TAG_VOCAB` at a JSON file to use your own. Existing tags are reported, never rewritten.

### 🛡️ Safer Writes
- **No more vanishing tags** ([#100](https://github.com/esoltys/luminous-mcp/issues/100)): Artist profile updates now run as a single transaction, so a write can't be lost to a change made at the same moment by the Luminous desktop app. Tags that are also parent groups in your Genres page are flagged so you know a tag is doing double duty.
- **Schema 85 recognized**: `get_server_info` reports a library on Luminous schema 85 as compatible instead of flagging it.

### 🔌 Install & Packaging
- **Claude plugin** ([#74](https://github.com/esoltys/luminous-mcp/issues/74)): The repository is installable as a Claude Code plugin, and every tool now declares whether it only reads, writes, or changes playback so clients can ask for confirmation sensibly.
- **Direct install guidance**: The README now explains the Claude directory's limits for local servers and the install paths that work today: the signed `.mcpb` bundle, the plugin and manual configuration.
